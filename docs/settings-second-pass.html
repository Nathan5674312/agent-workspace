Settings, Second Pass

The first survey covered an agent app and a notes app. Widening it to a desktop shell, a modern editor and two reference taxonomies turned up a category the app has nothing of — and two things that are defects rather than gaps.

Hermes · source Obsidian · asar Notion · state.json Zed · default.json VS Code · docs Logseq · docs

A filled dot means the rows were read off a real file on this machine. Hollow means documentation only — a weaker source, and labelled as such.

The finding

The first pass surveyed what a document configures. It missed what a window configures.

Notion and Zed both carry a layer underneath the document settings: the desktop shell. This app has none of it. Verified by grep across src/main/ — every one of these is absent, and index.ts hardcodes width: 1600, height: 1000 with no persistence.

autoUpdater Tray globalShortcut setLoginItemSettings disableHardwareAcceleration window bounds

Window bounds is the one to build first: cheapest, most universally expected, and the only one here a person notices on every single launch.

Six more findings

Two are defects, not gaps

Defect

The secret-blocking claim has no implementation

Zed ships private_files and redact_private_values. This app needs that more than Zed does — it spawns agents against the vault root via claude.ts, and a shell via terminal.ts. The machine's own CLAUDE.md says secrets are blocked from agent file tools "by design". Nothing in this repo implements that. The list belongs beside HIDDEN and SKIP, which already exist and already work.

Zed default: **/.env*, **/*.pem, **/*.key, **/*.cert, **/secrets.yml

Defect

Backups grow forever

save() writes a pre-edit copy on every save and nothing prunes — versions.ts says so in its own header. No reference app has a retention setting because none of them keeps a copy per save, so this one was found by absence rather than precedent.

Measured on the real vault: 187 files · 871 KB in .backups/

Gap

Updates are missing, and shipping depends on them

Roadmap note 11 settles on Developer ID and notarization with download-from-the-site. That has no store to push updates through, so the updater is the delivery mechanism rather than a nicety. The setting is small; the machinery behind it is a shipping decision.

Gap

UI scale and editor font size are two settings, not one

The first pass proposed "editor font size". Zed separates ui_font_size from buffer_font_size; Notion has zoomFactor for the whole UI. Different blast radii: one reflows every pane and is an accessibility control, the other affects prose only. UI scale is nearly free here — tokens.css is already in rem so the layout scales with it.

Gap

Telemetry should be a statement, not a toggle

Zed ships two telemetry switches; VS Code has a whole group. This app should ship neither. Nothing under src/ calls fetch, axios, XHR, WebSocket, http.request or createServer, and index.html enforces connect-src 'none'. A toggle implies something to turn off, and would be the only dishonest control in the app.

Overturned

The ban on themes was right, and has been satisfied

The first pass excluded themes because "arbitrary themes discard the measurement". Seven palettes shipped the same day, and the objection was met rather than ignored: each is solved to the founder's own contrast ratios, and the suite re-measures all of them on every run. What was wrong was assuming a theme picker implies arbitrary themes.

Still excluded

Everything the first pass ruled out, except themes. The eight CodeMirror-dependent editor settings — line numbers, vim bindings, live preview, folding, auto-pair, tab size and the rest — remain one decision, not eight settings. That is the roadmap's Markdown-support project, not a settings task.

Notes for whoever builds this
  • Sections become Vault · Editor · Appearance · Agent · About. Two new.
  • The dialog is a real <dialog> with showModal(), so focus trap, Escape, focus restore and top layer are the platform's job. A nav rewrite must not turn it back into a div.
  • Dependent settings nest rather than grey out, past the second one — Obsidian's rule, and it scales where disabling does not.
  • Every new key needs a row in sanitize(). That function is the single trust boundary, and an unvalidated key is how junk from a hand-edited settings.json reaches the renderer.
